**P1.** E / T / P:

(a) **Electricity price.** E: historical prices with the conditions around them
(demand, weather, season). T: given tomorrow's conditions, output a price.
P: mean absolute error in øre/kWh on days the model never saw. *Regression, so
P is an error, not an accuracy.*

(b) **Card fraud.** E: past transactions labelled fraud/legitimate. T: flag one
new transaction. P: **not** accuracy — fraud is perhaps 0.1% of transactions,
so a model that never flags anything scores 99.9%. Precision and recall on the
fraud class. *This is next week's whole subject.*

(c) **Chess.** E: games played against itself, plus their outcomes. T: choose a
move in a position. P: win rate against a fixed opponent. *Reinforcement — the
experience is generated by acting, not handed over as a dataset.*

**P2.**

(a) Grouping students by courses — **unsupervised**. No label; you're looking
for structure that's already there.
(b) Minutes a bus is late — **regression**. Label is a number.
(c) X-ray fracture — **classification**. Two categories.
(d) Robot walking — **reinforcement**. Acts, gets rewarded for not falling.
(e) Which of 26 letters — **classification**, multiclass. Still categories;
having 26 rather than 2 changes the metrics, not the kind.

**P3.** 100% train, 62% test is **overfitting** — a 38-point gap. The model
memorised the training set. Any two of:

- **More data.** The most reliable fix, and usually the most expensive.
- **A simpler model.** Fewer parameters, less capacity to memorise. A shallower
  tree, a lower-degree polynomial.
- **Regularisation.** Penalise complexity during training.
- **Fewer / better features.** Especially if a feature is leaking the answer.
- **Cross-validation**, so you find this out before you have burned your test set.

Not "train longer" — that makes it worse.

**P4.** 500 houses, 8 features, predicting price:

```
X.shape == (500, 8)
y.shape == (500,)
```

With one feature, `X.shape == (500, 1)` — still 2-D. `y` is unchanged. If you
wrote `(500,)` for X with one feature, that's the error that will bite you in
sklearn; the fix is `X.reshape(-1, 1)`.

**P6.** 10,000 unlabelled emails. As it stands this is **unsupervised** — and
you cannot build the spam filter you were asked for, because a spam filter is a
supervised classifier and there is nothing to learn "spam" from.

First move: **get labels.** Label a few hundred by hand, or find a proxy (what
users moved to the junk folder). Only once labels exist is this a classification
problem.

The point of the question: the most common real failure is not choosing a poor
model, it is discovering that the data does not support the task at all.
Noticing that on day one is worth more than any modelling trick.
